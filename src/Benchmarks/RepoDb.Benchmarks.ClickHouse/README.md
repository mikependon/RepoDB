# 📈 RepoDb.Benchmarks.ClickHouse

Benchmarks comparing RepoDB against Dapper, Entity Framework Core, and Linq2Db on ClickHouse. See the [main Benchmarks README](../README.md) for the full methodology, ORM list, and Enterprise Notice.

## ❓ Why this Benchmark?

This benchmark exists to give **visibility** into how RepoDB performs against other widely used .NET ORMs on ClickHouse, and to do so in a way that avoids bias — the same schema, the same dataset, and the same operations are run against every ORM in a single pass, and all of the benchmarking code is open for anyone to read or challenge.

That said, results produced here run on infrastructure local to this repository. If your organization is evaluating RepoDB for ClickHouse workloads, we strongly encourage you to run this benchmark on your **own environment** — your own hardware, your own ClickHouse configuration, and your own data shape — before making a collective and conclusive decision. See the [Enterprise Notice](../README.md#-enterprise-notice) in the main Benchmarks README for more on why this matters.

## 🐝 NHibernate is not included

NHibernate ships no ClickHouse dialect or driver, official or community. There's nothing to point it at, so it's left out entirely rather than approximated.

## ▶️ Running the Benchmark

1. Start a ClickHouse instance using the repository's root [docker-compose.yml](../../../../docker-compose.yml):

   ```bash
   docker compose up -d clickhouse
   ```

2. Run the benchmark project in `Release` configuration:

   ```bash
   cd src/Shared/RepoDb.Benchmarks/RepoDb.Benchmarks.ClickHouse
   dotnet run -c Release
   ```

3. Select the benchmark(s) you want to run from the interactive BenchmarkDotNet menu.

> ⚠️ Always run in `Release` configuration — Debug builds produce misleading results.

By default, the benchmark connects using:

```
Host=127.0.0.1;Port=8123;Username=default;Password=RepoDB2026;Database=RepoDb;Protocol=http;
```

and uses the following admin connection (pointing at the `default` database) to create the `RepoDb` database if it doesn't already exist:

```
Host=127.0.0.1;Port=8123;Username=default;Password=RepoDB2026;Database=default;Protocol=http;
```

To target a different instance or credentials, set these environment variables before running:

```bash
export REPODB_CONSTR="Host=<your-host>;Port=8123;Username=default;Password=<your-password>;Database=RepoDb;Protocol=http;"
export REPODB_CONSTR_CLICKHOUSEDB="Host=<your-host>;Port=8123;Username=default;Password=<your-password>;Database=default;Protocol=http;"
```

Results are written to `BenchmarkDotNet.Artifacts` as Markdown, HTML, and console reports.

## 📦 Client Library

This benchmark uses [ClickHouse.Driver](https://www.nuget.org/packages/ClickHouse.Driver) (connecting over ClickHouse's HTTP interface) throughout — including [RepoDb.ClickHouse](../../../Providers/RepoDb.ClickHouse), [RepoDb.ClickHouse.BulkOperations](../../../Providers/RepoDb.ClickHouse.BulkOperations), and Linq2Db (via `ClickHouseProvider.ClickHouseDriver`). Entity Framework Core uses [ClickHouse.EntityFrameworkCore](https://www.nuget.org/packages/ClickHouse.EntityFrameworkCore), the official EF Core provider from the ClickHouse project itself, also built on `ClickHouse.Driver` — it already supports EF Core 10, so no version pin was needed here.

### Two things that are different about ClickHouse

- **No identity/auto-increment.** ClickHouse has no session-wide scope identity, sequence, or auto-increment mechanism of any kind — `RepoDb.ClickHouse`'s `GetScopeIdentity` throws `NotSupportedException` by design. Every `Id` in this benchmark, including the ones generated by `InsertAllRepoDbBenchmarks`, is assigned explicitly by the client; the insert benchmarks start their generated IDs past the seeded row range so they don't collide with the rows `GetAll`/`GetFirst` rely on.
- **No row-level `UPDATE`.** ClickHouse implements updates as asynchronous `ALTER TABLE ... UPDATE` mutations rather than a synchronous `UPDATE ... SET ...` statement, so the `Person` table uses `ENGINE = ReplacingMergeTree` and the Dapper update benchmark issues the ClickHouse-specific mutation syntax directly (RepoDb and Linq2Db generate the correct provider-specific syntax internally).
