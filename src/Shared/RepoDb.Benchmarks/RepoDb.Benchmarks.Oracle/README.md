# 🔺 RepoDb.Benchmarks.Oracle

Benchmarks comparing RepoDB against Dapper, Entity Framework Core, Linq2Db, and NHibernate on Oracle Database. See the [main Benchmarks README](../README.md) for the full methodology, ORM list, and Enterprise Notice.

## ❓ Why this Benchmark?

This benchmark exists to give **visibility** into how RepoDB performs against other widely used .NET ORMs on Oracle Database, and to do so in a way that avoids bias — the same schema, the same dataset, and the same operations are run against every ORM in a single pass, and all of the benchmarking code is open for anyone to read or challenge.

That said, results produced here run on infrastructure local to this repository. If your organization is evaluating RepoDB for Oracle workloads, we strongly encourage you to run this benchmark on your **own environment** — your own hardware, your own Oracle configuration, and your own data shape — before making a collective and conclusive decision. See the [Enterprise Notice](../README.md#-enterprise-notice) in the main Benchmarks README for more on why this matters.

## ▶️ Running the Benchmark

1. Start an Oracle Database Free instance using the repository's root [docker-compose.yml](../../../../docker-compose.yml):

   ```bash
   docker compose up -d oracle
   ```

2. Run the benchmark project in `Release` configuration:

   ```bash
   cd src/Shared/RepoDb.Benchmarks/RepoDb.Benchmarks.Oracle
   dotnet run -c Release
   ```

3. Select the benchmark(s) you want to run from the interactive BenchmarkDotNet menu.

> ⚠️ Always run in `Release` configuration — Debug builds produce misleading results.

By default, the benchmark connects using:

```
User Id=system;Password=RepoDB2026;Data Source=127.0.0.1:1521/FREEPDB1;
```

Unlike SQL Server/PostgreSQL/MySQL, this benchmark does not create a database — Oracle databases/pluggable databases are provisioned ahead of time (the `FREEPDB1` pluggable database ships with the `database/free` Docker image), so the benchmark only creates the `Person` table inside the target schema.

To target a different instance or credentials, set this environment variable before running:

```bash
export REPODB_CONSTR="User Id=<your-user>;Password=<your-password>;Data Source=<your-host>:1521/<your-service>;"
```

Results are written to `BenchmarkDotNet.Artifacts` as Markdown, HTML, and console reports.

## 📦 Client Library

This benchmark uses [Oracle.ManagedDataAccess.Core](https://www.nuget.org/packages/Oracle.ManagedDataAccess.Core) (Oracle's official managed ODP.NET driver) throughout — including [RepoDb.Oracle](../../../Providers/RepoDb.Oracle), [RepoDb.Oracle.BulkOperations](../../../Providers/RepoDb.Oracle.BulkOperations), and NHibernate (via `OracleManagedDataClientDriver`). Entity Framework Core uses [Oracle.EntityFrameworkCore](https://www.nuget.org/packages/Oracle.EntityFrameworkCore), Oracle's official EF Core provider. Linq2Db targets the managed driver via `OracleProvider.Managed`.

The `Person` table's `"Id"` column uses a native Oracle 12c+ `GENERATED BY DEFAULT AS IDENTITY` column, and every identifier (table and column names) is double-quoted to keep exact casing — both EF Core's and Linq2Db's Oracle providers quote identifiers to preserve case, so this keeps the schema and every ORM's generated SQL consistent.
